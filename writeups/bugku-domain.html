Bugku 域名解析：改 hosts 骗过浏览器

2026-09-29 · 约 7 分钟 · Bugku 练习场

题目要求用某个域名访问，但那域名根本解析不到靶机。那就自己当一次 DNS。

题目信息

平台Bugku 练习场
类型Web · 环境配置
知识点DNS 解析顺序、hosts 文件、ipconfig /flushdns

这题严格说不算「打」出来的，而是「配」出来的。它需要的操作在真实工作里也很常用——本地调试、上线前验证、复现 CDN 问题，都绕不开 hosts。

现象：域名打不开，IP 能打开

题目给了一个域名，要求用它访问靶机。直接打开，浏览器报「无法访问此网站」，连页面都出不来。但把域名换成靶机 IP，页面正常显示。

这说明服务和网络都没问题，坏在「域名到 IP」这一步：这个域名在公网 DNS 里查不到，或者压根指向别处。题目为什么要这么设计？因为靶机上很可能用 Host 请求头做判断——只有请求头里的 Host 是那个域名时才返回 flag。用 IP 访问时 Host 就是 IP，条件不成立，所以必须让浏览器「以为」自己在访问那个域名。

浏览器把域名变成 IP 的顺序

浏览器解析一个域名，大致按这个顺序找答案：

  • 浏览器自己的 DNS 缓存（Chrome 还有一层内部缓存，chrome://net-internals/#dns 可以清）
  • 操作系统 DNS 缓存
  • hosts 文件
  • 配置的 DNS 服务器（运营商或公共 DNS），必要时逐级向上问

顺序里有个细节值得记：不同浏览器对 hosts 和自身缓存的先后处理并不完全一致，Chrome 有时会先用自己的缓存。所以改完 hosts 不生效，第一反应应该是清缓存，而不是怀疑自己写错了。这也是我第一次做这题卡住的原因——文件改对了，但浏览器还在用旧结果。

改 hosts：一行就够

Windows 的 hosts 文件在 C:\Windows\System32\drivers\etc\hosts，没有扩展名。它需要管理员权限才能改：用管理员身份打开记事本，或者普通记事本改完保存时会有拒绝访问的提示。文件里默认全是 # 开头的注释，在末尾加一行，格式是「IP 空格 域名」：

192.168.1.10 flag.bugku.com

保存即可。一行可以写多个域名，用空格隔开；但一个域名只能对应一个 IP，写多行只有第一行生效。分隔符用空格或 Tab 都行，写成冒号就错了。

Linux 和 macOS 是 /etc/hosts，格式一模一样，改的时候要 sudo：

sudo sh -c 'echo "192.168.1.10 flag.bugku.com" >> /etc/hosts'
cat /etc/hosts | tail -n 3

用记事本存 hosts 时注意别存成 hosts.txt。Windows 资源管理器默认隐藏已知扩展名，看起来文件名没变，实际已经多了 .txt，系统不会读它。

刷新缓存并验证

改完不一定马上生效，因为系统还缓存着旧结果，连「查不到」这个结论也会被缓存。Windows 下刷新：

ipconfig /flushdns
ping flag.bugku.com
curl -s -H "Host: flag.bugku.com" http://192.168.1.10/

Linux 用 systemd-resolved 的话是 sudo resolvectl flush-caches。ping 能解析到靶机 IP，就说明 hosts 生效了；然后回浏览器用域名访问，拿到 flag{...}。

如果还不生效，按这个顺序排查：hosts 那一行有没有写错（IP 和域名之间是空格，不是冒号）、是不是存成了 hosts.txt、浏览器缓存清没清、代理有没有开着——代理可能会自己解析域名，直接绕过 hosts，这种时候关掉代理再试。

引申：hosts 劫持

hosts 是个很有用的调试工具，但它也是恶意软件的常见手法。改掉 hosts，把银行、支付、软件更新服务器的域名指向攻击者的 IP，用户地址栏里输入的域名完全正确，打开的却是钓鱼页面，证书告警还常常被用户点掉。整个过程不需要碰 DNS，也不需要用户点任何可疑链接。

排查思路就是反过来读这个文件：看有没有不属于自己的条目、DNS 设置有没有被改、用公共 DNS 解析同一个域名做对比。防御上，hosts 应该只有管理员可写，EDR 可以对它的修改行为告警；企业环境里更彻底的做法是把控制放在 DNS 层，而不是指望每台机器的 hosts 都干净。

这题本身很小，但它让我第一次真正理解「域名只是给人看的，机器只认 IP」。理解了这句话，再看 Host 头、SNI、证书校验这些东西，就都能串起来了。
