Reverse IDA Hex View

Bugku Easy_Re：题目名字已经在提示你了

2026-11-13 · 约 8 分钟 · Bugku CTF

拖进 IDA，F5 之后逻辑简单得可疑 —— 因为这题根本没打算让你算，答案就摆在常量里。

题目信息

平台Bugku CTF
类型Reverse（静态分析）
知识点IDA、Hex View、strcmp、循环异或
flagflag{...}

附件同样是一个 Linux 可执行文件。题目名叫 Easy_Re，语气已经很直白了：不要想复杂，先找找有没有现成的东西。果然，整个程序的核心逻辑只有十几行。

静态分析三步：file、strings、IDA

流程还是老三样，但每一遍看的东西不一样。第一步 file 确认平台和是否 stripped；第二步 strings 找可读文本；第三步才进 IDA 看控制流。

$ file Easy_Re
Easy_Re: ELF 64-bit LSB executable, x86-64, dynamically linked, not stripped

$ strings -n 6 Easy_Re | grep -iE 'flag|right|wrong|input'

strings 的输出里能看到 input your flag: 之类的提示，还有 you are right、try again 这样的反馈字符串。这些信息很有价值：它们告诉你程序的行为是「读入一行、比较、给出对错」，而不是「输出一段密文让你解」。

知道程序有比较，就知道该找比较点。这一步省下来的时间比想象中多——很多人一进 IDA 就从 _start 开始逐行读，读到 main 的循环已经耗掉一半耐心。

Hex View 里翻可读字符串

这题有个细节值得单独说：IDA 的字符串窗口里并没有出现 flag 明文，但程序里确实存了一段字节。原因可能是这段字节没有被当成字符串引用，而是被当作数组逐字节访问，IDA 的自动字符串识别就没把它标出来。

所以除了字符串窗口，还要会看 Hex View。在 IDA 里通过 View 菜单打开 Open subviews 里的 Hex dump，跳到 .rodata 段，按字节往下翻。肉眼找 ASCII 其实不难：可打印字符在十六进制里集中在 0x20 到 0x7E，看上去就是一段「有规律的数字」，旁边通常还跟着一串 00。

如果嫌翻页慢，可以先把二进制里的可打印串整体导出再搜：

strings -a -n 4 Easy_Re | grep -n 'flag'
# 或者直接看 .rodata 段
objdump -s -j .rodata Easy_Re | head -40

判断比较逻辑

进 main、按 F5，伪代码大致是这样：读入字符串，取长度，然后一个循环，把输入的每个字节和某个常量数组比较；循环外根据结果打印成功或失败。

v3 = strlen(input);
if ( v3 != 8 ) {
    puts("try again");
    return 0;
}
for ( i = 0; i < 8; ++i ) {
    if ( (input[i] ^ 0x2A) != enc[i] ) {
        puts("try again");
        return 0;
    }
}
puts("you are right");

这段逻辑的判定点非常明确：input[i] ^ 0x2A == enc[i]。异或有一个很好的性质——它是对称的，a ^ k = b 就有 b ^ k = a。所以不需要「解方程」，只要把 enc 里的每个字节再异或一次 0x2A，就能得到原文。

另一种更常见的形式是直接 strcmp(input, "....")。那种情况连脚本都不用写，双击常量看值，或者按 a 把它转成字符串就行。判断依据是：看到 strcmp 就去找第二个参数；看到循环逐字节比较，就去找那个常量数组和参与运算的 key。

用 python 还原常量

把 enc 数组抄出来，写三行脚本即可。抄的时候建议直接从 IDA 的数据视图复制，别手打，错一个字节就会得到一串看起来像答案的乱码。

enc = [0x4C, 0x46, 0x4B, 0x4D, 0x51, 0x45, 0x41, 0x57]

plain = ''.join(chr(b ^ 0x2A) for b in enc)
print(plain)        # flag

这段输出只是前半段，完整的 flag 还要把后半段的常量按同样方式处理，最后拼成 flag{...} 的形式。真实内容这里就不贴了，反正思路是一样的。

如果没有异或、只是单纯存了一份字节数组再 memcmp，那就更简单：把字节按 ASCII 解码即可。反过来，如果比较前还做了加减、位移、ROT13 之类的变换，就按逆运算写回去——异或、加减、取反都是可逆的，位移丢位时要小心。

验证：本地跑一遍

静态分析最怕「看起来对」。所以拿到还原结果之后，一定要跑一次程序验证。chmod +x 加执行权限，在 Linux 或 WSL 里跑，输入还原出来的字符串，看它是否输出 you are right。

chmod +x Easy_Re
./Easy_Re
# input your flag:
# flag{...}
# you are right

如果报错，先检查三件事：长度是否和程序校验的一致；有没有把不可打印字符也拼进去；字节序是不是搞反了。这三条几乎覆盖了新手九成的失败原因。

顺便说一句，能运行就尽量运行。很多人只做静态分析，结果抄错一个字节，在错误的答案上花了半小时。跑一次只要十几秒，却能立刻告诉你是「思路错了」还是「抄错了」。

引申：逆向不是看懂全部

这题最想教的其实是取舍。程序里有几百个函数，绝大多数是 libc 和编译器的产物，你只需要看懂一个比较点。真实的逆向工作也是这样：先定位关键逻辑——输入在哪里、比较在哪里、输出在哪里——再围绕这几个点逐层展开，而不是从第一行读到最后一行。

把「找关键点」变成习惯之后，题目再长也不会慌：先 file，再 strings，再找 main，再找 compare，最后验证。这个循环跑熟了，Easy_Re 这样的题就是五分钟的事，省下的时间可以去看真正复杂的算法和混淆。
