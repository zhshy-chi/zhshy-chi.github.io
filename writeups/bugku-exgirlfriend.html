Web strcmp 数组绕过

Bugku 前女友：strcmp 的返回值陷阱

2026-10-22 · 约 7 分钟 · Bugku CTF

代码里写着 if(strcmp($a,$b)==0)，看起来密不透风，但 strcmp 在 5.3 之后遇到数组会返回 NULL。

题目信息

平台Bugku CTF · Web
类型strcmp 返回值滥用 / 数组绕过
知识点strcmp 语义、NULL == 0、松散比较
目标让 strcmp($a, $b) == 0 成立却不给出正确答案

题面：一句 strcmp 判等

题目只有一句话：「猜猜前女友的名字」。输入框提交后，代码把我和答案做一次字符串比较，相等就输出 flag。 源码大概长这样，短得让人无从下手： 

<?php
$answer = '一个我也不知道的名字';   // 服务端保存的正确答案

if (isset($_GET['name'])) {
    $name = $_GET['name'];
    if (strcmp($name, $answer) == 0) {
        echo 'flag{...}';
    } else {
        echo '你不是他';
    }
}

名字我猜不到，爆破也不现实。但这段代码有个细节值得盯：比较的是 strcmp() 的返回值，而不是两个字符串本身； 而返回值是用 == 0 判的，不是 === 0。这两个「不是」就是入口。

strcmp 的语义与那个 NULL

strcmp($a, $b) 的约定是：相等返回 0，$a 大返回正数，$b 大返回负数。听起来很干净，但它的参数类型是 string。 如果我传一个数组进去，PHP 在 5.3 之后的版本里会告警「expects parameter 1 to be string, array given」，然后返回 NULL。 

<?php
var_dump(strcmp(array('x'), 'abc'));   // NULL，并伴随一条 Warning
var_dump(NULL == 0);                   // bool(true)
var_dump(NULL === 0);                  // bool(false)

关键就是最后两行。PHP 的 == 是松散比较，NULL 会被当成「空值」处理，和整数 0 比较时结果为 true。 于是 strcmp(数组, 字符串) == 0 成立 —— 我根本不需要知道答案是什么。

再补一句 PHP 的松散比较表：NULL == false、NULL == ""、NULL == 0、NULL == array() 全都为 true。 也就是说 strcmp() 只要返回 NULL，不管代码拿它跟 0、false 还是空字符串比，都会「相等」。这就解释了为什么有些题把判断写成 if (!strcmp(...))，照样被数组打穿。

利用：把参数变成数组

HTTP 参数名后面加一对中括号，PHP 就会把它解析成数组。这是整题唯一需要记的 payload 形状： 

curl "http://靶机/?name[]=whatever"
# 响应：flag{...}

$_GET['name'] 现在是一个 array('whatever')，strcmp() 收到数组返回 NULL， NULL == 0 为真，判断通过。整个链条里没有任何一步需要我知道「前女友」叫什么。

如果两边都由我控制，形状还会更简单：?v1[]=x&v2[]=y，两个参数都变成数组，strcmp() 各返回一个 NULL， NULL == NULL 依然成立。这种「两次输入必须一致」的题（确认密码、确认 token）基本都是同一个套路。

顺带说一句版本差异：PHP 8 对内部函数的字符串参数会直接抛 TypeError，这招在新版本上会变成 500。 所以看到「本地能打、线上 500」时，先确认目标 PHP 版本，而不是怀疑 payload 写错了。

另一条路：哈希比较的 == 与 ===

这题还有一个「同父异母」的考点：如果代码不比 strcmp，而是比哈希，比如 if (md5($a) === md5($b))， 那就轮不到 NULL 出场，得换思路 —— 传数组让 md5() 返回 NULL，两个 NULL 用 === 比也是相等的。 这正好说明 === 也不是万能的：它保证类型一致，但保证不了「函数真的返回了一个哈希」。

如果代码写的是 md5($a) == md5($b)，还有经典的 0e 碰撞：两个不同的字符串，md5 值都是 0e 开头且后面全是数字， 松散比较时都被当成 0。这跟 NULL == 0 是同一类问题的不同皮肤：松散比较把「不同的东西」判成了相等。

真实代码里这种写法并不罕见：有人用 strcmp($token, $expected) 比 API token，有人用 == 比两个哈希。 平时看不出问题，一旦参数能传成数组（比如把 JSON 解析结果直接丢进去），判断就静默失效 —— 没有报错、没有日志，只有一次成功的越权。

踩坑记录

  • 一开始传 ?name= 空字符串，没用 —— strcmp('', $answer) 返回的是非零值。
  • 试过在字符串里塞 \0 或者超长串，思路跑偏了；这题的入口在「类型」，不在「内容」。
  • 浏览器里手敲 ?name[]=x 有时会被转义成 %5B%5D，这不影响，PHP 一样解析成数组。
  • 如果页面把 Warning 显示出来了，会看到 strcmp() expects parameter 1 to be string, array given，别急着关掉报错，它其实在告诉你「函数收到了错误类型」。
  • 本地复现只要三行：用 php -r 跑一下 var_dump(strcmp([], 'x'))，就能看到 NULL 和那条 Warning。先在本地验证语义，比在靶机上盲试快得多。

防御建议

  • 比较字符串用 ===，并且先确认两侧都是字符串（is_string）。
  • 密码、token、哈希一律用 hash_equals($known, $user) 做恒定时间比较，别用 ==。
  • 入口统一类型校验：参数该是字符串就拒绝数组，别让 [] 悄悄改变类型。
  • 打开错误日志但关闭页面回显，避免 Warning 泄露内部结构。
