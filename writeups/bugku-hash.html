Crypto MD5 哈希识别

Bugku 散列：把哈希先认出来再说

2026-11-02 · 约 8 分钟 · Bugku CTF

给你一串 32 位十六进制，先别急着「爆破」。先确认它到底是 MD5、NTLM 还是别的 —— 认错了算法，后面所有努力都是白费。

题目信息

平台Bugku CTF
类型Crypto / 哈希
知识点哈希识别、字典爆破、加盐存储

先别急着爆破

题目给了一段十六进制：

e10adc3949ba59abbe56e057f20f883e

很多人的第一反应是丢进在线「解密」站。但「解密」这个词对哈希是不成立的：哈希是单向函数，没有密钥，也就不存在逆向。那些站点做的其实是「查表 + 跑字典」，能找到只说明原文在它的库里。

所以在动手之前，先确认它是哪种哈希。这一步花不了两分钟，却能省掉后面一小时的瞎试。

实际上识别还可以更省事：把字符串丢进 CyberChef 的 Magic，或者用 Kali 自带的 hash-identifier，它会按可能性排序列出候选。但工具的输出只能当线索，不能当结论 —— 尤其是 32 位的串，MD5 和 NTLM 在长度上完全一样，工具也分不出来。

先数长度，再看前缀

长度 / 前缀常见算法
32 位 hexMD5、NTLM、LM
40 位 hexSHA1
64 位 hexSHA256
96 位 hexSHA384
128 位 hexSHA512
$1$MD5-crypt（Linux）
$2a$ / $2y$ / $2b$bcrypt
$6$SHA512-crypt

长度只能缩小范围，不能定论：32 位可能是 MD5，也可能是 Windows 里的 NTLM。这时候要看上下文 —— 题目是 Web 站，还是给了域环境？另外，如果有盐，长度会变化（md5($pass.$salt) 仍是 32 位，但值完全不同），只靠长度就更难判断了。

用 hashid 与 hash-identifier 确认

这两个工具都是按长度、字符集、前缀做模式匹配，给出候选列表和置信度：

hashid e10adc3949ba59abbe56e057f20f883e
hashid -m e10adc3949ba59abbe56e057f20f883e
hash-identifier

输出会写 MD5 [Hashcat Mode: 0]、NTLM [1000] 之类。加 -m 会直接给出 hashcat 的模式号，省得自己查表。记住工具只是给建议：它说「可能是」，最终还得结合场景自己判断。

字典比暴力破解更实际

确认是 MD5 之后，别想着穷举 32 位空间 —— 那是不可能的。真实题目里的密码几乎都是弱口令，rockyou 这类字典命中率很高：

hashcat -m 0 -a 0 hash.txt rockyou.txt
john --format=raw-md5 --wordlist=rockyou.txt hash.txt

这题的串解出来是 123456，一个教科书级别的弱口令，整个过程不到一秒。这也正好说明了问题：不是攻破算法，而是密码太弱。

用字典时注意两点：模式号必须和算法对上（-m 0 是 MD5，-m 1000 是 NTLM），模式错了会一直显示未找到；另外记得加 --show 回看已经跑出来的结果，别重复跑。

MD5 碰撞与长度扩展（入门概念）

两件事要分清。碰撞是找两个不同的输入、得到相同的哈希，MD5 在 2004 年就被王小云团队攻破，所以它不该再用于签名或完整性校验。长度扩展是另一回事：MD5 属于 Merkle–Damgård 结构，知道 hash(secret||msg) 和 secret 的长度，就能在不认识 secret 的情况下算出 hash(secret||msg||padding||append)。所以「用 md5(secret.msg) 当签名」是错的，正确的做法是 HMAC。

顺带一提，很多「MD5 解密」网站会把常见串直接缓存在库里，看着像秒解，其实只是命中了别人的字典。真遇到随机盐，它们一样无能为力 —— 这也从反面说明盐的价值。

盐到底解决了什么

彩虹表是「预先算好的哈希到原文」大表。不加盐时，同一个密码永远得到同一个哈希，一张表可以打穿所有用户；加了盐，每个用户的哈希都不同，表就失效了，攻击者只能对单个目标现算。

但盐不解决「密码太弱」。123456 加盐后仍然会被字典命中，只是要多花一点时间。所以慢哈希（bcrypt、argon2）和盐要一起用：盐负责让预计算失效，慢负责让逐个尝试变贵，两者缺一不可。

该怎么存密码

MD5、SHA1、SHA256 都太快了，快就意味着 GPU 每秒能算几十亿次。正确做法是慢哈希加每用户随机盐：bcrypt（cost 10 以上）、scrypt、argon2id。盐让彩虹表失效，慢让爆破成本变高。再补两条：登录失败提示统一，限制尝试次数。

这题给我的最大收获不是「解出了一个 MD5」，而是养成了一个顺序：先识别，再选工具，最后才动手。哈希题如此，别的题也一样。

顺带一句：如果库里已经存了不加盐的 MD5，正确的做法不是「再套一层 MD5」，而是下次登录时用新算法重算并平滑迁移。
