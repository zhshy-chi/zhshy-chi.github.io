Web PHP弱类型 is_numeric

Bugku 矛盾：is_numeric 与弱类型比较

2026-10-01 · 约 8 分钟 · Bugku

题目想让我传个数字，又不让我传数字 —— 这种自相矛盾的条件，通常意味着它在用「弱类型」。这篇笔记从一段两行判断的源码出发，把 is_numeric() 和 == 的两套语义拆开看。

题目信息

平台Bugku CTF 练习平台
类型Web / PHP 代码审计
知识点PHP 弱类型、is_numeric、松散比较、PHP 8 版本差异
环境PHP 5.6 / PHP 7，本地另起 PHP 8 做对照

题面：先看这段矛盾的代码

题目给了几行源码，逻辑短得一眼能看完：先取 $_GET['num']，然后做两次判断。第一次，如果 is_numeric($num) 为真，就 die() 掉，提示「不能是数字」；第二次，如果 $num == 1 为真，就输出 flag。 

<?php
$num = $_GET['num'];
if (is_numeric($num)) {
    die('num 不能是数字');
}
if ($num == 1) {
    echo 'flag{...}';
}
?>

第一次读完我是有点懵的：它既要一个不是数字的东西，又要这个东西等于 1。按正常人的直觉，这题像是出错了。但在 CTF 里碰到这种「自相矛盾」，基本可以反过来理解 —— 出题人不是在为难你，而是在提示你：这两个判断对「数字」的理解不是同一套规则，中间一定有缝隙。

PHP 的弱类型比较到底怎么比

PHP 是弱类型语言，== 是松散比较，比较之前会先做类型转换。在 PHP 5 和 PHP 7 里，当一个字符串和一个数字用 == 比较时，字符串会被转成数字再比。转换规则非常宽松：从字符串开头开始读，能读成数字的部分就当作结果，遇到第一个不能构成数字的字符就停下，后面的内容直接忽略。

所以 "1abc" 会被转成 1，"1.0abc" 会被转成 1.0，"1e3abc" 会按科学计数法转成 1000。反过来，is_numeric() 检查的是整个字符串的字面形状：从头到尾必须是一个合法的数字写法，"1abc" 里带着字母，它直接返回 false。一个看「像不像数字」，一个看「转成数字后是多少」，这就是全部矛盾来源。

为什么 1abc 能同时骗过两个判断

把两条规则代进题面：is_numeric("1abc") 是 false，第一个 if 不成立，程序继续往下走；接着 "1abc" == 1，字符串先被转成 1，1 == 1 成立，flag 就打印出来了。同一个输入，在两个判断里被解释成了两个不同的东西。所以这道题真正要记的不是 payload，而是这个习惯：看到校验函数和使用点不是同一个函数，就去想它们对同一个值的理解会不会不一致。

利用过程

知道了原理，payload 就没什么技术含量了，直接拼在查询串里： 

curl "http://靶机地址/?num=1abc"

浏览器里访问 ?num=1abc 也一样能拿到结果。为了确认自己不是碰巧撞对的，我又把 ?num=1、?num=abc、?num=1.0abc 各发了一遍：传纯数字被第一关拦下，传纯字母在第二关失败，只有「数字开头、后面跟垃圾字符」的写法能过去。这一步对照实验很重要，它能证明你理解的是规则，而不是背下了一个答案。

PHP 8 之后的版本差异

这题在 PHP 8 上会直接失效，原因值得单独记一笔。PHP 8 收紧了「字符串与数字比较」的规则：当数字和一个非数字字符串比较时，不再把字符串转成数字，而是把数字转成字符串，然后按字符串比较。于是 1 == "1abc" 变成了 "1" == "1abc"，结果是 false，payload 当场死掉。同样地，PHP 7 里 0 == "abc" 为真的经典怪癖，在 PHP 8 里也变成了 false。

另一个容易混的点是 is_numeric() 自己的变化：从 PHP 8.0 开始，字符串末尾的空白字符被允许，is_numeric("1 ") 返回 true。但这在本题里帮不上忙 —— 它让第一关直接成立，反而更过不去。所以看到这类题，第一件事应该是确认靶机的 PHP 版本，版本不对，思路就得整个换掉。

记住一句话：弱类型题的答案往往不在 payload 里，而在「哪个函数解释了这个值」里。换版本等于换规则，先问环境再动手。

踩坑与复盘

  • 一开始试了 ?num[]=1，想用数组绕过 is_numeric，结果数组和 1 比较也是 false，白忙一场。
  • 试过 ?num=1%20，在 PHP 5 里 is_numeric("1 ") 是 false，但第二关能过；可惜我当时在 PHP 8 环境里测，两关都过不去，绕了很久才想起看版本。
  • 最后确认：这题吃的就是 PHP 5/7 的松散比较，理解规则比记 payload 有用得多。

防御建议

写代码时，如果某个值要当数字用，就别先把它当字符串校验一遍再丢进比较里。统一用 is_numeric() 加 intval() 转换，比较时用 === 而不是 ==，让「校验」和「使用」落在同一个类型上。另外，升级到 PHP 8 能消掉一大批这类历史怪癖，但别把它当成修复手段 —— 代码里该收紧的地方还是得收紧。
