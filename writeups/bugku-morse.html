Bugku /.- ：从摩斯密码开始的第一道密码题

2026-11-04 · 约 7 分钟 · Bugku CTF

一串点和划，还有斜杠。斜杠不是字符，是分隔符。这道题真正想教的不是摩斯表，而是「先分清哪个符号是数据、哪个符号是结构」。

题目信息

平台Bugku CTF
类型Crypto（编码类）
知识点摩斯密码、分隔符、URL 编码、Python 解码
flagflag{...}

题目页面非常干净，只有一段由点、短横线和斜杠组成的文本，没有附件，也没有提示。第一眼看上去像乱码，但只要认出它是摩斯密码，剩下的基本就是体力活加一点耐心。

摩斯密码到底长什么样

摩斯密码的规则其实只有三条：每个字母由一至四个「点」或「划」组成；字母和字母之间用空格分开；单词和单词之间用斜杠分开。点代表短信号，划代表长信号，在真实电报里两者的时长大约是一比三，所以听电报名手能直接听出节奏。

它是一套完全公开的对照表，不涉及任何密钥，所以只要分组正确，解码结果就是唯一的，不存在「解不出来」这种情况。也正因为规则太简单，出题人能动手脚的地方只剩两个：把分隔符藏起来，或者在解出来的明文上再套一层编码。这道题两样都做了。

另外，摩斯码不区分大小写，标准表里也没有花括号。所以当解码结果里「flag」后面跟着奇怪的东西时，那基本是第二层编码在等你。

先肉眼分组，再交给工具

我最开始的错误做法是把整段文本直接粘进在线解码器，结果出来一堆问号。原因不在解码器，而在复制过程中分隔符丢了：网页里的换行被吃掉、行尾空格被裁掉，于是「.-」和「.-..」粘成了一个不存在的码。后来我改成先手动规整，再解码，一次就通了。

规整的目标只有一件事：让斜杠和空格各就各位。斜杠是词分隔，空格是字母分隔，两者不能混用；有些题目喜欢用换行代替斜杠，那就先把换行换成斜杠再处理。

# 用换行当词分隔的题目：先把换行换成斜杠
tr '\n' '/' < morse.txt > step1.txt
# 再把连续空格压成一个，避免出现空字段
tr -s ' ' < step1.txt > clean.txt

分组之后还要看一眼自己的表有没有缺。数字和标点的摩斯码更长（通常五到六个符号），更容易和字母混；如果题目只要求字母，就别把数字表塞进同一张字典。

肉眼检查的顺序我一般是这样：先数斜杠确认词数，再挑最短的码（一个点、一个划）去对表验证空格位置，最后才整段跑。

解码之后还有一层：URL 编码

摩斯解出来的明文并不是 flag，而是形如 flag%u7b...%u7d 的东西。第一次看到的时候我以为是乱码，盯着看了半天才反应过来：%u7b 和 %u7d 正是左花括号和右花括号的老式 Unicode 编码（%uXXXX 形式），出题人把花括号也编码了，就是为了不让你一眼看出 flag 的形状。

这里有个很常见的坑：Python 的 urllib.parse.unquote 只认 %XX 这种八位编码，碰到 %uXXXX 会原样保留，一点用都没有。要么换一个支持 %u 的在线工具，要么自己写正则替换。我选了后者，因为顺手，而且以后遇到同类题可以直接复用。

import re

s = 'flag%u7b...%u7d'

# %u7b 是 4 位十六进制，转成对应字符即可
s = re.sub(r'%u([0-9a-fA-F]{4})', lambda m: chr(int(m.group(1), 16)), s)
print(s)          # flag{...}

顺手说一句，%u 并不是标准 URL 编码，而是早期 JavaScript 的 escape() 留下的历史包袱；标准写法是 %7B 和 %7D。两种都要认识。

自己写一个二十行的解码器

在线工具当然够用，但我还是照着对照表自己写了一遍。理由很简单：写一遍之后，「空格是字母分隔、斜杠是词分隔、查表前先 strip」这三件事就再也不会记错了。核心只有两步：先按斜杠切词，再按空格切字母，逐段查表。

CODE = {
    '.-': 'A', '-...': 'B', '-.-.': 'C', '-..': 'D', '.': 'E',
    '-..-.': 'F', '--.': 'G', '....': 'H', '..': 'I', '.---': 'J',
    '-.-': 'K', '.-..': 'L', '--': 'M', '-.': 'N', '---': 'O',
}
# 真实题目要把 26 个字母和 10 个数字补全

def decode(text):
    words = text.strip().split('/')      # 斜杠 = 词分隔
    out = []
    for w in words:
        letters = w.split()              # 空白 = 字母分隔
        out.append(''.join(CODE.get(x, '?') for x in letters))
    return ' '.join(out)

print(decode('.... . .-.. .-.. --- / .-- --- .-. .-.. -..'))
# HELLO WORLD

这段里最值得记的是 w.split()：不带参数时它会把连续空格、行首行尾的空白一并处理掉，比 split(' ') 稳得多。后者遇到两个连续空格会切出一个空字符串，查表自然查不到，于是结果里莫名多出问号——我第一次卡住就是因为这个。

踩坑与复盘

  • 把整段文本丢给在线工具，分隔符在复制时丢了，却以为是题目写错。
  • 把 %u7b 当成乱码，绕了十几分钟才发现它是花括号。
  • 摩斯码不区分大小写，题目要的却是小写，最后补了一句 lower()。
  • 斜杠和反斜杠长得像，从截图里抄的时候看错了一次，分组直接错位。

复盘下来，这类题考的不是聪明，而是「每一步都验证一下」。分组对不对，拿几个最短的码对表就知道；结果是不是最终答案，看形状像不像 flag；中间出现 %、= 这类符号，基本说明还有一层。

一点引申：编码不是加密

摩斯密码、URL 编码、Base64、十六进制，这些都属于「编码」：把信息换一种表示方式，规则公开，任何人拿到都能还原。加密不一样，它需要密钥，不知道密钥就真的还原不出来。CTF 里所谓的「密码题」，第一层往往是编码，真正涉及密码学的部分（RSA、AES、异或）通常藏在后面几层。

分清这两件事的意义在于：看到一串奇怪的字符，先问「它是哪种编码」，而不是「它是什么密码」。后者会让你去猜密钥，前者只需要查表。这道题从头到尾没有密钥，只有两张对照表和一次正则替换——它真正想让你学会的，是这种「分层剥离」的直觉。
