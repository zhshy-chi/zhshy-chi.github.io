Reverse IDA 静态分析

Bugku 入门逆向：第一眼看汇编

2026-11-11 · 约 9 分钟 · Bugku CTF

第一次把程序拖进 IDA，满屏 mov 和 call。其实这题只要认出 66h 6ch 61h 67h 就够了，剩下的都是编译器帮忙生成的东西。

题目信息

平台Bugku CTF
类型Reverse（静态分析）
知识点file、strings、IDA 反编译、栈上立即数、ASCII
flagflag{...}

附件是一个 Linux 可执行文件。题目名就叫「入门逆向」，所以它不会在算法上为难人，重点是把「怎么开始看一个程序」这件事演示一遍。我第一次打开它的时候完全不知道该看哪儿，下面按我实际的顺序记录。

file 与 strings：两个不花钱的步骤

在打开反编译工具之前，先用两个命令收集信息。它们只要几秒钟，但能决定你后面要看什么。

$ file reverse1
reverse1: ELF 64-bit LSB executable, x86-64, version 1 (SYSV),
dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, not stripped

$ strings -n 6 reverse1 | head -40

not stripped 是个好消息：符号表还在，函数名是 main 而不是 sub_4006D6，在 IDA 左侧的函数窗口里可以直接跳过去。如果是 stripped，就要从入口点 _start 里找 __libc_start_main 的第一个参数，多绕一步。

strings 这题没有直接给出答案，只看到一些编译器生成的版本号、GCC 的报错字符串、libc 的函数名。这也正常——如果 flag 以标准字符串的形式存在，strings | grep flag 就结束了，题目不会这么出。但这一步仍然值得做，因为它能把「有线索」和「没线索」区分开。

拖进 IDA，找到 main

IDA 打开后默认停在程序入口，不是 main。左侧函数窗口里搜 main，双击进去，然后按 F5 生成伪代码。对于新手来说，伪代码比汇编好读太多，先看伪代码建立整体印象，再回汇编看细节，是更省力的路径。

这题的 main 异常短。伪代码里能看到一串对局部数组的逐字节赋值，紧接着把这个数组的地址传给输出函数。回到汇编视图，就是连续的一串 mov，把立即数一个字节一个字节写到栈上的连续位置：

mov     byte ptr [rbp-20h], 66h
mov     byte ptr [rbp-1Fh], 6Ch
mov     byte ptr [rbp-1Eh], 61h
mov     byte ptr [rbp-1Dh], 67h
mov     byte ptr [rbp-1Ch], 7Bh
mov     byte ptr [rbp-1Bh], 2Dh
mov     byte ptr [rbp-1Ah], 2Dh
...
lea     rax, [rbp-20h]
mov     rdi, rax
call    puts

看到这种「地址连续、每次减一、值是两位十六进制」的模式，就应该想到：这是在拼一个字符串。编译器把 char s[] = "..." 这种短字符串初始化，优化成了逐字节写入，而不是放在 .rodata 里。所以 strings 找不到它，但它在栈上完完整整地存在。

一串 mov：立即数就是字符

66h、6Ch、61h、67h 单独看没有意义，但它们落在 ASCII 的可打印范围内。0x66 是 'f'，0x6C 是 'l'，0x61 是 'a'，0x67 是 'g'。连起来就是 flag 的开头，说明方向完全正确。

接下来要做的只是把这一串立即数按顺序抄下来。抄的时候注意两点：一是顺序，栈地址从低到高，rbp-20h 比 rbp-1Fh 更靠近低地址，所以按地址递增的顺序拼；二是别漏字节，中间如果出现 00h，那是字符串的结束符，不是内容。

伪代码里其实更直观：IDA 会把它显示成 v4[0] = 0x66; 这样的赋值序列，或者干脆识别成 char v4[24] = "flag..."。如果 F5 直接给出了字符串，那连转换都省了；这题我第一次按 F5 时只看到数组赋值，说明 IDA 没有把它识别成字符串常量。

十六进制还原成字符串

把字节序列转成字符串，最省事的是 Python。四个字节也好，四十个字节也好，写法都一样：

nums = [0x66, 0x6C, 0x61, 0x67]
print(''.join(chr(n) for n in nums))      # flag

如果字节很多，从 IDA 里一个个抄太慢，可以直接把汇编选中复制成一个文本文件，用正则批量提取 6Ch 这种两位十六进制：

import re

asm = open('main.asm', encoding='utf-8').read()
nums = [int(x, 16) for x in re.findall(r'([0-9A-Fa-f]{2})h', asm)]
print(bytes(nums).decode('latin-1'))

用 latin-1 解码是为了稳妥：字节序列里偶尔会混进不可打印字符，用 utf-8 解码可能直接抛异常，而 latin-1 能一对一映射，不会丢信息。看清楚之后再决定怎么裁剪。

复盘：逆向的第一次胜利

  • 先 file 再看架构，避免在错误的工具上浪费时间。
  • strings 没结果不代表没线索，只是线索不在字符串表里。
  • 看到连续 mov 加 lea 取地址，先想「这是不是在拼字符串」。
  • 两位十六进制加 h 结尾，几乎一定是 ASCII 或机器码，先试着当字符看。

这道题给我的最大收获不是 flag，而是「读程序可以从中间开始」。以前我总觉得逆向必须从第一行读到最后一行，实际上可以先找输出、找比较、找可疑常量，再往回推。这题就是典型的「常量即答案」：程序没有任何输入，也没有校验逻辑，它只是把一段数据打出来而已。

顺带一提，这类静态题不需要运行程序。如果程序是 Linux 的 ELF，在 Windows 上跑还得装 WSL 或虚拟机，静态分析反而更省事。等遇到需要动态验证的题（比如带反调试、需要跟踪运行时内存），再上 gdb 或 x64dbg 也不迟。

引申：逆向第一步永远是先看字符串和常量

真实的逆向工程里，字符串往往是最快的突破口：报错信息、路径、URL、加密库的名字、版本号，都能帮你快速判断程序用了什么技术栈。即使字符串被混淆或加密，字符串的「引用位置」也仍然是重要的锚点——谁在读它、读完之后做了什么，比字符串本身更有价值。

把这条习惯固定下来：file 看类型，strings 看线索，IDA 看逻辑，最后才是动态调试。每一步都有明确的产出，卡住的时候也知道该退回哪一步，而不是对着满屏汇编发呆。
