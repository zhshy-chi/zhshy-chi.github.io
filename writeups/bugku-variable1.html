Web 变量覆盖 PHP超全局

Bugku 变量1：用 $GLOBALS 覆盖变量

2026-10-12 · 约 8 分钟 · Bugku CTF

题目里有个变量挡住了我，那我就从外部把同名变量塞进去。这篇记录我第一次真正弄懂「可变变量」和 $GLOBALS 是怎么一回事。

题目信息

平台Bugku CTF · Web
类型PHP 变量覆盖 / 符号表读取
知识点可变变量、$GLOBALS、extract 与 parse_str
目标读出被藏在变量里的 flag

先看题面：flag 在某个变量里

页面很朴素，一段高亮出来的源码。大意是：flag 被写进一个变量，程序拿我传进去的 args 去比较，通过才输出。 我第一反应是找那个比较逻辑、想构造一个能骗过判断的字符串，盯了两分钟才反应过来方向错了 —— 它不打算让我猜中 flag，它把「变量名」交给我了。 

<?php
include "flag.php";          // 文件里有一句 $flag = "flag{...}";
highlight_file(__FILE__);

$args = $_GET['args'] ?? '';
if (!preg_match('/^\w+$/', $args)) {
    die('args error');
}

// 把 $args 的值当成变量名，再取这个变量的值
var_dump($$args);

关键就在最后一行。$$args 不是「变量 args 的平方」，而是可变变量：先取 $args 的值（一个字符串），再把这个字符串当成变量名去取值。 所以传 ?args=flag，等价于 var_dump($flag)。我第一次也是这么想的，结果页面一片空白。

卡住的地方：名字不对

?args=flag 没有任何回显，说明符号表里没有叫 flag 的变量。这时候有两条路：硬猜变量名，或者把整张符号表倒出来。第二条更聪明，而 PHP 恰好把这张表本身也做成了一个变量。

$GLOBALS 是 PHP 的超全局数组，索引是全局变量的名字，值是变量本身。它是对符号表的引用而非副本：往 $GLOBALS['x'] 写东西，等于创建了 $x。 既然题目允许我用任意字符串当变量名，那传 GLOBALS 进去，它就会把整张表 dump 出来，flag 自然躺在里面。 

curl "http://靶机地址/?args=GLOBALS"
# 响应里能看到 ["flag"]=> string(38) "flag{...}"

为什么用户输入能改掉「本来只读」的变量

这里其实发生了两次「名字 → 值」的跳跃，我在笔记里是这么画的：

  • 第一跳：HTTP 参数 args=GLOBALS 变成 $_GET['args']，再赋给 $args。这步很普通，值只是个字符串。
  • 第二跳：$$args 拿这个字符串当变量名，去全局符号表里查。查哪张表？就是 $GLOBALS 那张。

所以严格说，$flag 没被修改过，我只是「按名字读」到了它。安全上这叫变量覆盖：程序把「变量名」这种元信息交给了用户，等于把符号表的读写权限一起交了出去。名字能选，值就能选。

另一类常见写法是 extract($_GET) 或 parse_str($str)：数组的键直接变成变量，访问 ?flag=x 就产生了 $flag。 区别在于 $$args 偏向「读」，extract 偏向「写」—— 后者能覆盖程序自己的判断变量，比如把 $isAdmin 改成 true。 

<?php
// 危险写法：用户的键名直接进了符号表
extract($_GET);
if ($isAdmin) {           // 访问 ?isAdmin=1 就能进来
    echo "welcome, admin";
}

还有个容易混的点：global $x; 是把全局变量「引进」当前作用域，改的还是同一个变量；而 $GLOBALS['x'] 是直接操作符号表本身。 两者都能改值，但后者不需要提前声明，配合可变变量就更危险 —— 只要名字对得上，什么变量都能碰。

踩过的几个坑

  • 只盯着「比较」两个字。以为要爆破或者构造 payload，其实题目考的是「能不能读到变量」，跟比较逻辑没关系。
  • 直接 ?args=flag 没回显。正确姿势是先枚举符号表，而不是硬猜变量名，$GLOBALS 就是那张表。
  • 写成 $_GLOBALS。少一个下划线就是未定义变量，页面白屏，很容易误以为被拦了。

引申：register_globals 与真实代码里的变量覆盖

老 PHP（5.4 之前）有个配置项 register_globals，打开后 GET/POST/Cookie 的参数会被自动注册成全局变量，等于全站默认开着 extract($_REQUEST)。 这个选项在 PHP 5.4.0 被移除，但影子还在：老 CMS 里常见的 foreach ($_GET as $k => $v) { $$k = $v; } 就是同一个洞。

另外，$GLOBALS 本身只是个普通数组，foreach ($GLOBALS as $k => $v) 就能把运行时的变量名和值全部打印出来。 我在本地调试 PHP 时经常用它看「到底有哪些变量还活着」，但换个位置，它就是标准的敏感信息泄露。

真实代码里变量覆盖的危害通常比「读一个 flag」严重得多：覆盖 $table、$class、$action 可以改 SQL 拼接、改包含的文件、 改反序列化的类名。所以我现在审计 PHP 代码会专门搜三个关键词：extract(、parse_str(、$$。看到它们就停下来想一句： 这个变量名，用户能不能控制？

防御建议

  • 别用 extract() / parse_str() 处理外部输入；非要用就加 EXTR_SKIP。
  • 干掉任何「变量名来自用户」的写法：$$name、${$name}、$obj->$prop。
  • 用固定白名单分发（switch ($action)），不要动态拼符号表。
  • 输出敏感值前，确认请求真的过了业务校验，而不是「名字对上就打印」。
