Bugku Web2：答案就写在源码注释里

2026-09-20 · 约 8 分钟 · Bugku 练习场

打开页面是个计算器，怎么算都提示错误。别急着算，先按 F12 —— 答案一直在注释里。

题目信息

平台Bugku 练习场
类型Web · 信息收集
知识点HTML 注释、源码审计、robots.txt、备份文件

这道题在 Bugku 的 Web 入门区，名字就叫 Web2，难度标得很低。但它教的东西比难度重要：一个「怎么都不对」的页面，第一反应应该是看它给你发了什么，而不是继续在里面操作。

页面第一眼：一道永远算不对的题

打开链接，页面朴素得不能再朴素：两个随机数字、一个输入框、一个提交按钮，让我算加法。我按正常流程算了一遍填进去，回车，红字提示答案错误。我以为是自己手滑，拿计算器重新按了一遍，还是错。第三遍我把加减乘除都试了，提示语连一个字都没换过。

这个时候人很容易开始钻牛角尖：是不是要按十六进制算？是不是数字每次刷新都会变？是不是得连续答对十次？我在这个方向上耗了差不多十分钟，直到反应过来——我在跟一个前端页面较劲，而这个页面上没有任何一样东西是我能相信的。

按 F12 之后看到的

开发者工具才是这道题真正的入口。右键「检查」或者直接按 F12，Elements 面板显示的是浏览器解析后的 DOM；如果想看服务器原样吐出来的文本，用 Ctrl+U 查看网页源代码，或者在地址栏手写 view-source: 前缀。找注释的时候后者更干净，它不会帮你补全标签，也不会把 JS 动态插入的节点混进来。

顺手记一个常识：有些页面会写 oncontextmenu="return false" 来禁右键，但 F12 和 Ctrl+U 属于浏览器自身功能，JS 拦不住。右键被禁，不等于源码被藏起来。

curl -s "http://靶机地址/" | head -n 40
curl -s "http://靶机地址/" | grep -n "<!--"
# 浏览器里也可以直接访问：view-source:http://靶机地址/

注释里的答案，和提交方式

在 body 开头、表单上方，有一行被折叠的灰色文字，展开是 <!-- ... --> 包起来的内容。里面就是 <flag 已隐去>，格式是标准的 flag{...}，前后没有任何编码或变形。

它没走前端校验，也没藏在 JS 变量里，就是一行 HTML 注释。注释对渲染不可见，但它会随 HTML 原样发到客户端，所以任何能看源码的人都看得到。我把这串字符复制出来，回平台粘进提交框，回车，通过。整个过程里没有「算」这个动作。

注释不是保险箱。真实项目里我见过注释写着测试账号、内网地址、待删除的接口。上线前把注释当公开内容审一遍，比事后补救便宜得多。

把「先看源码」变成肌肉记忆

这题做完，我给自己理了一个「打开一个站先看什么」的顺序，每一步都只要几秒钟：

  • 源码和注释：Ctrl+U 之后搜 <!--、TODO、FIXME、key、flag
  • robots.txt：看它不想让爬虫去哪些目录，往往就是考点
  • 备份与源码泄露：www.zip、backup.zip、index.php.bak、.git/
  • 响应头：Server、X-Powered-By 用来判断语言和框架
  • 目录扫描：找没有链接入口的页面

都不高级，但它们是信息收集的地基。CTF 里它决定你能不能找到入口，真实项目里它决定你审计从哪一行开始。很多题不是难在利用，而是难在你根本没看见那行注释。

curl -s http://靶机地址/robots.txt
curl -s -o /dev/null -D - http://靶机地址/    # 只看响应头
curl -s -I http://靶机地址/backup.zip

复盘：这题真正考的是什么

踩的坑前面说了：把时间花在「怎么算对」上，而不是「这题在考什么」。后来我给自己加了一条反射：页面表现越反常，越要先看它发了什么给我——源码、响应头、请求参数，三样看完再谈逻辑。

防御角度，这题对应的是「敏感信息泄露」。HTML 注释、JS 里的硬编码常量、source map、.git 目录，本质都一样：把不该交给客户端的东西交了出去。写代码时把注释当公开内容，部署时把 .git、备份文件、测试页面挡在 web 根目录之外，这两条做到就能挡掉很大一部分。
