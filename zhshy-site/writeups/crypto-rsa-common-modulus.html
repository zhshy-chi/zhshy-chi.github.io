NSSCTF Crypto：RSA 共模攻击与低加密指数

2026-09-12 · 约 10 分钟 · NSSCTF

题目给了同一个 n、两把不同的 e，以及对同一条明文的两个密文。 一次贝祖等式就能把明文捞出来 —— 但先得看懂它为什么成立。

这是一篇示例文章，用来演示正文排版。换成你自己的 writeup 后，把这段提示删掉即可。

题目给了什么

n  = 0xa1b2...（1024 bit，两次加密完全相同）
e1 = 65537
e2 = 17
c1 = 0x4f19...
c2 = 0x9c2d...
# 同一条明文 m

两个密文、同一个模数、不同的公开指数 —— 这是共模攻击（common modulus attack）的标准形状。 原理不复杂，但很多题解直接甩脚本，我第一次看的时候完全不知道 s1 s2 是从哪冒出来的。

为什么能直接解

RSA 加密是两个同余式：

c1 ≡ m^e1 (mod n)
c2 ≡ m^e2 (mod n)

如果 gcd(e1, e2) = 1，由扩展欧几里得（贝祖等式）一定能找到整数 s1, s2 使得： 

s1·e1 + s2·e2 = 1

把两边同时作用在 m 上：

c1^s1 · c2^s2
  ≡ m^(e1·s1) · m^(e2·s2)
  ≡ m^(e1·s1 + e2·s2)
  ≡ m^1
  ≡ m   (mod n)

也就是说，只要两个指数互素，不需要分解 n，也不需要私钥， 就能把密文重新组合成明文。这就是共模攻击的全部原理。

注意：s1 或 s2 可能是负数。负数次幂在模意义下要用逆元处理，不能直接 pow(c, s, n)。

脚本

用 gmpy2 的 gcdext 求系数，invert 处理负指数：

import gmpy2
from Crypto.Util.number import long_to_bytes

n  = 0xa1b2c3...
e1, e2 = 65537, 17
c1, c2 = 0x4f19..., 0x9c2d...

g, s1, s2 = gmpy2.gcdext(e1, e2)      # s1*e1 + s2*e2 = g
assert g == 1, "gcd(e1, e2) != 1，共模攻击不适用"

def pow_signed(base, exp, mod):
    """支持负指数的模幂：c^(-k) = (c^(-1))^k"""
    if exp >= 0:
        return pow(base, exp, mod)
    return pow(gmpy2.invert(base, mod), -exp, mod)

m = (pow_signed(c1, s1, n) * pow_signed(c2, s2, n)) % n
print(long_to_bytes(int(m)).decode(errors="ignore"))

跑出来就是 flag。全程毫秒级，因为没有做任何「难」的计算。

顺带：低加密指数的小根攻击

如果题目不是共模，而是 e = 3 且明文很短，会有另一个常见漏洞： 当 m^3 < n 时，模运算根本没起作用，密文就是 m^3 本身，直接开三次方即可。 

m, exact = gmpy2.iroot(c, 3)
if exact:
    print(long_to_bytes(int(m)))   # 开方是整数，说明没被模运算截断

更一般的情形是 m^e = c + k·n，需要对 k 做小范围遍历， 这就是「小指数 + 广播攻击」的雏形。识别特征同样是：e 很小，且拿到的密文长度和 n 差不多。

踩坑记录

  • invert 报错：说明 c 和 n 不互素。 这种情况更走运 —— 直接 gcd(c, n) 就分解了 n，等于白送私钥。
  • 明文转字节失败：long_to_bytes 出来是乱码，通常是明文被 padding 过， 或者 m 解错了一位。先 hex() 看头是不是 flag{ / NSSCTF{。
  • 指数不互素：gcd(e1, e2) = g > 1 时，贝祖等式只能得到 m^g， 还需要对 m^g 开 g 次方（配合小根攻击）才能恢复 m。

复盘

这类题的价值不在脚本，而在于「看到两个密文 + 同一个 n」时能立刻想到贝祖等式。 我现在会先问三个问题再动手：

  1. n 是同一个吗？是 → 共模攻击。
  2. e 很小吗？是 → 小根 / 广播攻击。
  3. n 能被分解吗？能 → 直接算 d，其他都是多余的。

先把攻击面缩小，再写代码，比上来就抄脚本快得多。

防御视角

  • 同一条消息不要用两把不同的公钥加密，尤其是同一个模数 —— 这直接把安全性打没了。
  • 加密前做 OAEP / PKCS#1 v1.5 padding，让 m 接近 n 的长度，同时打断确定性。
  • e 不要取太小，65537 是经过验证的选择。
